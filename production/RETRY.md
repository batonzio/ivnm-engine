# Targeted retry v1
After a completed QA report: python production/retry.py plan. Only lines without a selected seed qualify; a mastering failure alone does not trigger synthesis. Two additional seeds per round, at most four additional takes per line. Preserve all existing task data, voice, normalized script and speed; no voice substitution or overwriting WAV. Run pipeline.py synth --engine ENGINE --retry for each engine with nonempty retry-tasks.json using its existing isolated environment, then retry.py merge and pipeline.py judge. Merge validates task/report hashes, identity of task metadata, result completeness and hashes of generated WAVs before updating manifests. Rejudging can reuse all valid existing takes, including unchanged lines; it still repeats ASR and mastering. No automatic ranking on uncalibrated continuity features. CI injects a controlled failed Pocket line into metadata of an existing successful demo, preserves original WAV hashes, generates only that line, then rejudges. Not evidence that all audible stutters can be fixed. No publication.
